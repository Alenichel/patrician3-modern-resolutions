# Fast-forward sea-map crash investigation

## Evidence

Two Windows Application Error events occurred on 2026-10-31 at 19:50:55
and 19:52:04 local time. Both report `Patrician3.exe`, `ddraw_dll.dll`,
exception `0xc0000005`, and module offset `0x8e00a`.
The user reported fast-forwarding while a ship was moving on the sea map.

The second crash has a local minidump. It records a failed **read** in the
indexed-color blitter, with the sea-map draw call on the stack.
The caller at `Patrician3.exe+0x4ace0` passed this rectangle:

```text
source:       X=-378, Y=0
destination:  X=0,    Y=42
size:         width=3156, height=1398
```

The negative source coordinate comes from the centered camera. The normal
camera tests did not exercise this separate rendering path. The first crash
has the same fault signature; only the second dump was available for analysis.

## Cause and correction

The fast-forward sea renderer forwards camera X directly to a native source
copy without clipping a negative source origin. Centering the camera alone
therefore makes this path capable of reading outside the image allocation.

The correction wraps this specific sea-map call. For the mod's centered
rectangle, it makes two valid source copies:

```text
left margin: source=(3062, Y), destination=(X,     Ydest), size=(378,  H)
map body:    source=(0,    Y), destination=(X+378, Ydest), size=(2778, H)
```

The first copy uses the existing neutral right-hand extension of the
generated 3440-pixel image. The second starts at a nonnegative source X.
Together they cover the original destination exactly, retaining the map's
position relative to ships and labels. Other source rectangles pass through
unchanged. Original executables and DLLs remain unchanged on disk.

## Validation

- The call-site signature matches once in the inspected game code.
- `tests/check_safe_blit.py` reproduces the invalid captured rectangle and
  executes the production x86 hook for six boundary/passthrough cases.
- It checks source bounds, destination coverage, map placement, the cdecl
  stack, and callee-saved registers. The maximum vertical camera case is included.
- Existing camera-hook emulation remains green in 40 cases.
- On 2026-11-01, the user confirmed that the real-game fast-forward retest
  with a moving ship succeeded. The fix is now verified in that gameplay scenario.
- The dump, extracted memory, and private analysis scripts are not part of
  the repository or release package.
